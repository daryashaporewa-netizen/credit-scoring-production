# Benchmark нейронной сети кредитного скоринга

## 1. Цель экспериментов

Цель тестирования — сравнить производительность исходной нейронной сети PyTorch, модели ONNX и её квантованной INT8-версии.

В рамках экспериментов оценивались:
- качество прогнозирования;
- скорость инференса;
- размер моделей;
- производительность на CPU и GPU.

## 2. Описание модели

Для бинарной классификации использовалась нейронная сеть MLP, реализованная на PyTorch.

Архитектура: 37 → 64 → 32 → 1.

Модель обучалась на датасете Default of Credit Card Clients.

- Обучающая выборка: 19 200 объектов.
- Валидационная выборка: 4 800 объектов.
- Тестовая выборка: 6 000 объектов.
- Количество эпох: 20.
- Оптимизатор: Adam.
- Функция потерь: BCEWithLogitsLoss.

Лучшая модель выбиралась по ROC-AUC на валидационной выборке.

## 3. Оборудование и условия тестирования

Локальные эксперименты проводились на:

- Устройство: MacBook Air.
- Процессор: Apple M3.
- CPU: 8 ядер (4 Performance, 4 Efficiency).
- Оперативная память: 16 ГБ.
- GPU: Apple M3, вычисления через MPS.
- Python: 3.12.12.
- PyTorch: 2.15.0.
- ONNX: 1.23.2.
- ONNX Runtime: 1.32.0.

Для CPU-тестов использовался один вычислительный поток.

Измерения проводились после прогревочных запусков модели. Время загрузки весов и предобработки данных не включалось.

## 4. Проверка конвертации в ONNX

Корректность конвертации проверялась путём сравнения вероятностей дефолта для 6 000 тестовых объектов.

Результаты:

- Максимальная абсолютная разница: 1.49e-7.
- Средняя абсолютная разница: 1.61e-8.
- Совпадение предсказанных классов: 100%.

Проверка численной близости с использованием `assert_allclose` прошла успешно.

Таким образом, конвертация не привела к существенному изменению предсказаний на тестовой выборке.

## 5. Сравнение PyTorch и ONNX на CPU

| Batch size | PyTorch, мс | ONNX, мс | Ускорение |
|---|---:|---:|---:|
| 1 | 0.01267 | 0.00400 | 3.17x |
| 32 | 0.01765 | 0.00677 | 2.61x |
| 128 | 0.02047 | 0.01640 | 1.25x |

ONNX Runtime показал меньшую среднюю задержку во всех трёх сценариях.

Наибольшее относительное ускорение наблюдалось при batch size = 1.

Полные результаты представлены в `benchmark_results.csv`.

## 6. INT8-квантование

Для оптимизации ONNX-модели использовалось динамическое INT8-квантование.

### Качество и размер модели

| Метрика | FP32 | INT8 |
|---|---:|---:|
| ROC-AUC | 0.7766 | 0.7740 |
| Average Precision | 0.5546 | 0.5506 |
| Размер, КБ | 18.71 | 9.27 |

Размер модели уменьшился на 50.46%.

ROC-AUC снизился на 0.0026, Average Precision — на 0.0040.

### Производительность

При batch size = 32:

| Метрика | FP32 | INT8 |
|---|---:|---:|
| Mean latency, мс | 0.0066 | 0.0088 |
| P95 latency, мс | 0.0068 | 0.0105 |

Квантование уменьшило размер модели, но увеличило среднюю задержку инференса примерно на 33.3%.

Для данной компактной архитектуры INT8 не обеспечил ускорения на протестированном CPU.

Подробные результаты представлены в `quantization_results.csv`.

## 7. Сравнение CPU и GPU

Для PyTorch дополнительно проведено сравнение CPU и Apple GPU (MPS).

| Batch size | CPU, мс | GPU, мс |
|---|---:|---:|
| 1 | 0.0118 | 0.2223 |
| 32 | 0.0183 | 0.3018 |
| 128 | 0.0204 | 0.2780 |

CPU оказался быстрее GPU во всех протестированных сценариях.

Возможная причина — небольшая вычислительная сложность MLP и накладные расходы на запуск GPU-операций.

При измерениях GPU использовалась синхронизация MPS. Передача входных данных между CPU и GPU не включалась в замеры.

Полные результаты представлены в `benchmark_gpu_results.csv`.

## 8. Выводы

По результатам локального тестирования:

1. ONNX Runtime обеспечил более быстрый инференс по сравнению с PyTorch на CPU.
2. Конвертация в ONNX сохранила численную близость предсказаний.
3. INT8-квантование уменьшило размер модели на 50.46%, но не ускорило инференс.
4. Для компактной MLP использование Apple GPU не дало преимущества над CPU.

Для дальнейших экспериментов и развертывания в качестве основной модели выбрана ONNX FP32.

## 9. Ограничения экспериментов

Все измерения выполнены локально на MacBook Air M3.

Полученные результаты не являются оценкой производительности облачной инфраструктуры.

Тестирование пока не включает:
- облачные CPU/GPU-инстансы;
- одновременные HTTP-запросы;
- сетевые задержки;
- затраты ресурсов Kubernetes;
- длительные нагрузочные испытания.

Окончательная конфигурация production-инфраструктуры будет определена после дополнительных тестов в целевом окружении.

## 10. Воспроизведение экспериментов

Запуск из корня проекта с установленными зависимостями и доступными артефактами моделей:

```bash

python -m src.models.neural_network.convert_onnx
python -m src.models.neural_network.validate_onnx
python -m src.models.neural_network.benchmark
python -m src.models.neural_network.quantize
python -m src.models.neural_network.benchmark_gpu
```

Для воспроизведения результатов необходимы обученные веса модели и сохранённый преобразователь признаков.
